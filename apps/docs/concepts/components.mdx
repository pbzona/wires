`wires` has one central idea: **a primitive gate and a complex circuit expose the same interface.** Anything you define can be used as a building block inside something else.

## Component definitions

A `ComponentDefinition` is a reusable, immutable description of a component. There are two kinds:

| Kind | Created with | Behavior comes from |
| --- | --- | --- |
| `"primitive"` | [`gate()`](/reference/gate) | An explicit `evaluate` function |
| `"composite"` | [`circuit()`](/reference/circuit) | Other components wired together |

Both kinds have a `name`, a `kind`, flat lists of input and output pin names, and a `describe()` method. If a circuit declares [named bit groups](/reference/circuit#named-bit-groups), its [`ComponentDefinition`](/reference/types#componentdefinition) also records the names that belong to each group in `inputGroups` and `outputGroups`. For primitives, these maps are empty.

Definitions are frozen and hold no simulation state, so you can share one definition across any number of circuits and simulations.

## Instances

When a circuit calls `add(definition, name?, inputs?)`, it creates a `ComponentInstance`, which is one part made from that definition. Two parts made from the same definition are fully independent. They have different names, different hierarchical paths and separate signal values.

```ts
import { circuit } from "@pbzona/wires";
import { NOT } from "@pbzona/wires/components";

const TwoInverters = circuit(
  { name: "TwoInverters", inputs: ["a", "b"], outputs: ["x", "y"] },
  ({ inputs, add, output }) => {
    const first = add(NOT, { a: inputs.a }); // named "NOT#0"
    const second = add(NOT, { a: inputs.b }); // named "NOT#1"
    output("x", first.outputs.out);
    output("y", second.outputs.out);
  },
);
```

## Ports

A port is a named terminal on a component. Each port has:

- an `id` unique within its component, such as `"inputs.a"` or `"outputs.out"`
- a `name` and a `direction` (`"input"` or `"output"`)
- an `owner`, which is either an instance or the circuit being defined
- a `role` that says how the port can be used in the current circuit: `"source"` if it can drive a wire, `"sink"` if it can only be fed

Ports are structural references only. They never hold values.

### Sources

Inside a circuit, signals flow from **sources** to the inputs of parts and to the circuit's own outputs. A source is either:

- one of the circuit's own inputs (`inputs.a`), or
- an output of a part the circuit added (`g.outputs.out`).

A part's inputs (`g.inputs.a`) are never sources. You only ever say what *feeds* them. Using one as a source is a compile-time error, and the same check runs again at runtime.

## Connections

A connection links one source to one input or output. Each wiring call in a builder reads **destination ← source**:

| Call | Connects |
| --- | --- |
| `add(NOT, "not", { a: nand.outputs.out })` | `not`'s input `a` ← `nand`'s output |
| `feed(top.inputs.b, bottom.outputs.out)` | `top`'s input `b` ← `bottom`'s output |
| `output("out", not.outputs.out)` | the circuit's output `out` ← `not`'s output |

- **Fan-out is allowed.** One source can feed any number of inputs.
- **One driver per input.** Giving an input or output a second source throws a `CircuitError`.
- **Cycles are allowed.** Feedback is how memory works. See [Sequential logic](/guides/sequential-logic).

## Circuits and hierarchy

A circuit is a hierarchical graph of external ports, child instances and connections. Every element gets a stable hierarchical id rooted at `root`:

```text
root                     the circuit being simulated or described
root.inputs.a            one of its input ports
root.not                 a child instance named "not"
root.not.g               a NAND gate inside that child
root.not.g.outputs.out   that gate's output port
```

These ids are identical across runs, and they are the keys used by [`describe()`](/guides/introspection), [`elaborate()`](/reference/elaborate), `inspect()` and `trace()`.
