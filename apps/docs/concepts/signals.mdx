A signal is a discrete digital value:

```ts
type Signal = 0 | 1 | "X";
```

| Value | Meaning |
| --- | --- |
| `0` | Logic low |
| `1` | Logic high |
| `"X"` | Unknown or uninitialized |

## Unknown values

Every signal in a new simulation starts as `"X"`. External inputs stay unknown until you assign them with `set()`. Primitives decide how unknowns propagate. NAND, for example, follows this table:

| a | b | NAND |
| --- | --- | --- |
| 0 | X | 1 |
| X | 0 | 1 |
| 1 | X | X |
| X | 1 | X |
| X | X | X |

A `0` on either input forces the output high, so the unknown on the other input doesn't matter. In every other unknown case the result is unknown too.

The simulator never resolves `"X"` to `0` or `1` on its own. A latch that has never been set reports `"X"` on both outputs, which is the honest answer.

## Numbers, not booleans

Compare signals with `===`, not JavaScript truthiness. This gate returns the imported `X` constant when its output is unknown. Returning the literal `"X"` works identically and needs no import.

```ts
import { gate, X } from "@pbzona/wires";

const AND3 = gate({
  name: "AND3",
  inputs: ["a", "b", "c"],
  outputs: ["out"],
  evaluate: ({ a, b, c }) => ({
    out: a === 0 || b === 0 || c === 0 ? 0 : a === 1 && b === 1 && c === 1 ? 1 : X,
  }),
});
```

Passing `true`, `2` or `"x"` where a signal is expected fails to type-check, and throws a `SimulationError` at runtime.

## Groups are not signals

In a circuit declaration, [`bits("d", 8)`](/reference/circuit#named-bit-groups) names eight pins, not one integer-valued signal. Setting `d0` to `1` tells you nothing about `d1`: it can still be `"X"`.

Even two bits set on the same tick can reach their outputs at different times. Here `a` goes straight to `q0` while `b` passes through an inverter on its way to `q1`:

```ts
import { bits, circuit, simulate } from "@pbzona/wires";
import { NOT } from "@pbzona/wires/components";

const InvertOneBit = circuit(
  { name: "InvertOneBit", inputs: ["a", "b"], outputs: [bits("q", 2)] },
  ({ inputs, add, output }) => {
    const invert = add(NOT, "invert", { a: inputs.b });
    output("q", [inputs.a, invert.outputs.out]);
  },
);

const first = simulate(InvertOneBit).set({ a: 1, b: 1 }).step();
console.log(first.readAll()); // { q0: 1, q1: "X" }
console.log(first.step().readAll()); // { q0: 1, q1: 0 }
```

Grouping the outputs didn't add a delay to the first bit or skip the gate delay on the second.

## Helpers

`wires` exports a few small helpers for working with signals:

| Export | Description |
| --- | --- |
| `X` | The constant `"X"` |
| `SIGNALS` | `[0, 1, "X"]`, frozen |
| `isSignal(value)` | Type guard that is true for `0`, `1` and `"X"` |

<Note>
  High-impedance (`Z`) signals and multi-driver buses are out of scope for now. Each destination has exactly one driver.
</Note>
