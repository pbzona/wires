All types on this page are exported from `@pbzona/wires`. Import them with `import type`.

## Signal

```ts
type Signal = 0 | 1 | "X";
```

## SignalTransition

```ts
type SignalTransition = {
  readonly tick: number;
  readonly wire: string; // wire id: the path of the port that drives it
  readonly previous: Signal;
  readonly value: Signal;
};
```

## ComponentDefinition

`ComponentDefinition` describes a reusable primitive or composite. Its `name` is the definition name, `kind` is `"primitive"` or `"composite"`, and `describe()` returns a `ComponentDescription`.

| Port property | Contents for the [eight-bit register](/guides/eight-bit-register) |
| --- | --- |
| `inputs` | Flat names in declaration order: `d0` through `d7`, then `clock` and `load` |
| `outputs` | `q0` through `q7` |
| `inputGroups.d` | The eight data input names, starting at `d0` |
| `outputGroups.q` | The eight data output names, starting at `q0` |

The group maps are read-only. A definition with no groups (including every primitive) has empty maps. TypeScript infers group names, not widths. The builder checks how many sources you supply when you wire a group. An out-of-range index returns `undefined`, not a port; with `noUncheckedIndexedAccess`, TypeScript asks you to account for that. Use `.map()` to visit just the ports that exist.

## ComponentInstance

The part returned by `chip.add()` has `kind: "instance"`, its own `name`, its `definition` and two sets of ports. Its `inputs` are sinks; its `outputs` are sources. For a grouped instance, `part.outputs.q[3]` and `part.outputs.q3` refer to the same source port. These are builder references, not [`Signal`](#signal) values.

## Port, SourcePort, SinkPort

```ts
type Direction = "input" | "output";
type PortRole = "source" | "sink";

interface Port<Name extends string = string, D extends Direction = Direction, R extends PortRole = PortRole> {
  readonly kind: "port";
  readonly id: string; // e.g. "inputs.a", unique within the owner
  readonly name: Name;
  readonly direction: D;
  readonly role: R;
  readonly owner: ComponentInstance | CircuitScope;
}

type SourcePort = Port<string, Direction, "source">;
type SinkPort = Port<string, Direction, "sink">;

interface CircuitScope {
  readonly kind: "scope"; // the circuit currently being defined
  readonly name: string;
}
```

`SourcePort` is useful for variables that track a signal through a loop, like the carry in a ripple adder. `SinkPort` is what `chip.feed()` accepts as its destination: a part's input.

## InputWiring

`InputWiring` is the input object passed to `chip.add()`. A scalar pin takes one `SourcePort`; a group takes a `readonly SourcePort[]` of the matching width. For example, `{ d: first.outputs.q, clock, load }` gives a register eight data sources and two control sources. Any input pin left out must be fed later with `chip.feed()`.

## ComponentDescription

Returned by `describe()`. Plain, serializable data.

```ts
type ComponentDescription = {
  readonly id: string; // "root", "root.not", "root.not.g"
  readonly name: string; // instance name ("root" at the top)
  readonly parent: string | null;
  readonly definition: string;
  readonly kind: "primitive" | "composite";
  readonly ports: readonly PortDescription[];
  readonly components: readonly ComponentDescription[];
  readonly connections: readonly ConnectionDescription[];
};

type PortDescription = { readonly id: string; readonly name: string; readonly direction: Direction };
type ConnectionDescription = { readonly source: string; readonly destination: string };
```
