Use `circuit(spec, build)` to give a set of wired parts its own name and external pins.

## Parameters

<ResponseField name="spec.name" type="string" required>
  The definition name. Must be an identifier.
</ResponseField>

<ResponseField name="spec.inputs" type="readonly (string | BitGroup)[]" required>
  External inputs in declaration order: a string for one named pin, or `bits(name, width)` for a group.
</ResponseField>

<ResponseField name="spec.outputs" type="readonly (string | BitGroup)[]" required>
  External outputs, declared the same way. Input and output names must not collide.
</ResponseField>

<ResponseField name="build" type="(chip: CircuitBuilder) => void" required>
  A synchronous callback that adds parts and wires them. It runs **immediately**, exactly once, and its result is validated before `circuit()` returns.
</ResponseField>

## Returns

A frozen [`ComponentDefinition`](/reference/types#componentdefinition) with `kind: "composite"`.

## Named bit groups

Import `bits` from `@pbzona/wires`. In a `circuit()` spec, `bits("d", 8)` declares eight ordinary pins: `d0`, `d1`, …, `d7`. The name must be an identifier, and the width must be a positive integer. Use a group for related pins and strings for scalars: `[bits("d", 8), "clock", "load"]` keeps the controls named, not numbered.

A group name and every pin it generates must be distinct from all other input and output names. For example, neither `"d"` nor `"d0"` can appear elsewhere alongside `bits("d", 8)`. The rule also applies between groups: a group called `d1` would hide the existing `d1` pin.

A group is a builder convenience, not another port. The definition's `inputs` and `outputs`, the simulator and the workbench use the expanded names. [`gate()`](/reference/gate) takes only scalar names. See the [eight-bit register](/guides/eight-bit-register) for a complete example.

## CircuitBuilder

The examples call the builder `chip`. Every wiring call reads **destination ← source**.

<ResponseField name="inputs" type="object">
  The circuit's own inputs. Scalar names give you one source. A group name gives you its sources in index order: `chip.inputs.d[3]` is the same port as `chip.inputs.d3`.
</ResponseField>

<ResponseField name="add" type="(definition, name?, inputs?) => ComponentInstance">
  Adds a part made from any definition, and wires the inputs listed in `inputs`, an object like `{ a: source, b: source }`. Inputs you leave out must be wired later with `chip.feed()`. Without `name`, a deterministic name `<Definition>#<n>` is generated, and the inputs object moves to the second argument: `chip.add(NOT, { a: chip.inputs.a })`. The returned part exposes `outputs` (sources) and `inputs` (only for `chip.feed()`). For a grouped input, pass one source per bit: `{ d: first.outputs.q, clock, load }` wires each `d` bit from the matching `q` bit.
</ResponseField>

<ResponseField name="feed" type="(input: SinkPort, source: SourcePort) => void">
  Wires one input pin of a part you already added, not a whole group. This is how feedback loops are built, because the source can be a part added after the one it feeds.
</ResponseField>

<ResponseField name="output" type="(name, sourceOrSources) => void">
  Drives one scalar output from one source, or a whole output group from an array of sources: `chip.output("q", sources)` wires `q0` from `sources[0]`, `q1` from `sources[1]`, and so on. Each pin must be driven exactly once.
</ResponseField>

## Example

```ts
import { circuit } from "@pbzona/wires";
import { NAND, NOT } from "@pbzona/wires/components";

const AND = circuit(
  { name: "AND", inputs: ["a", "b"], outputs: ["out"] },
  (chip) => {
    const nand = chip.add(NAND, { a: chip.inputs.a, b: chip.inputs.b });
    const not = chip.add(NOT, { a: nand.outputs.out });
    chip.output("out", not.outputs.out);
  },
);
```

With feedback:

```ts
import { circuit } from "@pbzona/wires";
import { NAND } from "@pbzona/wires/components";

const SRLatch = circuit(
  { name: "SRLatch", inputs: ["setN", "resetN"], outputs: ["q", "qBar"] },
  (chip) => {
    const top = chip.add(NAND, { a: chip.inputs.setN });
    const bottom = chip.add(NAND, { a: chip.inputs.resetN, b: top.outputs.out });
    chip.feed(top.inputs.b, bottom.outputs.out);
    chip.output("q", top.outputs.out);
    chip.output("qBar", bottom.outputs.out);
  },
);
```

## Errors

These wiring and declaration errors throw `CircuitError`. Width mismatches are rejected, never padded or truncated.

| When | Problem |
| --- | --- |
| `bits()` | Invalid group name or width |
| `circuit()` call | Invalid or duplicate port names (including group names and expanded pins), invalid circuit name, missing builder |
| `chip.add()` | Not a definition, invalid, duplicate or reserved (`inputs`, `outputs`) instance name, or a component that isn't defined yet |
| `chip.add()` inputs | A group with the wrong number of sources, a pin wired both individually and through its group, an input name the part doesn't have, or a source that isn't a port, is a part's input, or belongs to another circuit |
| `chip.feed()` | The destination isn't a part's input, the source is invalid, or the input already has a source |
| `chip.output()` | A group with the wrong number of sources, an output name the circuit doesn't have, an invalid source, or an output that's already driven |
| After the builder returns | Child inputs left unconnected, outputs left undriven, or the builder returned a promise |
| Any builder method after the builder returns | The builder has finished and can't be used again |
