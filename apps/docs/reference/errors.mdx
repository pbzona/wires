Every error thrown by the library extends `WiresError`, which extends `Error`.

```text
WiresError
├── CircuitError
└── SimulationError
    └── StabilizationError
```

## CircuitError

A structural problem with a definition. The message includes the circuit name when known, and relative paths are used for anything inside it.

<ResponseField name="path" type="string | undefined">
  The name of the circuit or primitive involved, when known.
</ResponseField>

Thrown for:

- invalid names, duplicate port names, duplicate or reserved instance names
- a bit group with an invalid width, names that collide after expansion, or a group wired with too few or too many sources
- a connection in the wrong direction, a port that doesn't exist, or a port of a foreign instance
- multiple drivers for one sink
- unconnected child inputs and undriven outputs, all reported together
- adding a component that isn't defined yet (`chip.add()` received `undefined`)
- wire loops with no driving gate, found during elaboration
- builders that are asynchronous, or used after they finish

```text
AND: outputs.out has multiple drivers (inputs.a and inputs.b); each destination may have only one driver
```

## SimulationError

A runtime problem:

- `set()` with an unknown input or an invalid signal value
- `read()` with an unknown output
- invalid `simulate()` options
- a primitive evaluator that throws (the original error is kept as `cause`), returns a non-object, omits an output, returns an unexpected output, or returns an invalid signal

```text
Primitive NAND at root.not.g did not return output "out"
```

## StabilizationError

Thrown by `run()` when the circuit hasn't stabilized after `maxTicks` ticks in one call.

<ResponseField name="tick" type="number">The simulation time when the run stopped.</ResponseField>
<ResponseField name="ticksExecuted" type="number">The ticks executed by the failing `run()` call.</ResponseField>
<ResponseField name="maxTicks" type="number">The configured limit.</ResponseField>
<ResponseField name="recentChanges" type="readonly SignalTransition[]">Up to the 16 most recent transitions, oldest first. Recorded even when tracing is off.</ResponseField>
<ResponseField name="components" type="readonly string[]">The sorted paths of the primitive gates driving those signals.</ResponseField>

For the ring oscillator from [Sequential logic](/guides/sequential-logic#oscillators), with `maxTicks: 100`:

```text
Circuit did not stabilize after 100 ticks (maxTicks 100, current tick 104).
Recently changed signals:
  @88 root.inv2.g.outputs.out: 0 -> 1
  @89 root.gate.outputs.out: 1 -> 0
  @90 root.inv1.g.outputs.out: 0 -> 1
  ...
  @102 root.inv1.g.outputs.out: 0 -> 1
  @103 root.inv2.g.outputs.out: 1 -> 0
Components involved: root.gate, root.inv1.g, root.inv2.g
```

States are never modified, so after any error the state you called the method on is still valid. Change its inputs so the circuit can settle, or go back to an earlier state.

## Handling errors

```ts
import { CircuitError, SimulationError, StabilizationError, WiresError, simulate } from "@pbzona/wires";
import { SRLatch } from "@pbzona/wires/components";

try {
  const forbidden = simulate(SRLatch, { maxTicks: 20 }).set({ setN: 0, resetN: 0 }).run();
  forbidden.set({ setN: 1, resetN: 1 }).run();
} catch (error) {
  if (error instanceof StabilizationError) console.log("oscillating:", error.components);
  else if (error instanceof SimulationError) console.log("runtime problem:", error.message);
  else if (error instanceof CircuitError) console.log("bad circuit:", error.message);
  else if (error instanceof WiresError) console.log("other library error");
  else throw error;
}
```
