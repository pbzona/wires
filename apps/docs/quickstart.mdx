## Install

<CodeGroup>

```bash pnpm
pnpm add wires
```

```bash npm
npm install wires
```

```bash bun
bun add wires
```

</CodeGroup>

The package has two entry points:

| Import | Contents |
| --- | --- |
| `wires` | The engine: `gate`, `circuit`, `simulate`, `elaborate`, errors and types |
| `wires/components` | The standard library: `NAND`, `NOT`, `AND`, `OR`, `NOR`, `XOR`, `XNOR`, `HalfAdder`, `FullAdder`, `Mux`, `Demux`, `SRLatch` |

## Build and simulate a circuit

<Steps>
  <Step title="Define a primitive gate">
    A primitive has an explicit evaluation function. Here is NAND, the only gate you need to build everything else.

    ```ts
    import { gate } from "wires";

    export const NAND = gate({
      name: "NAND",
      inputs: ["a", "b"],
      outputs: ["out"],
      evaluate: ({ a, b }) => ({
        out: a === 0 || b === 0 ? 1 : a === 1 && b === 1 ? 0 : "X",
      }),
    });
    ```

    `wires/components` exports this exact gate, so the next steps import it from there.
  </Step>

  <Step title="Compose it into a circuit">
    A composite circuit adds parts one at a time, saying what feeds each part's inputs, then says what drives its outputs.

    ```ts
    import { circuit } from "wires";
    import { NAND } from "wires/components";

    export const AND = circuit(
      { name: "AND", inputs: ["a", "b"], outputs: ["out"] },
      ({ inputs, add, output }) => {
        const nand = add(NAND, "nand", { a: inputs.a, b: inputs.b });
        const not = add(NAND, "not", { a: nand.outputs.out, b: nand.outputs.out });
        output("out", not.outputs.out);
      },
    );
    ```

    Read it top to bottom: the inputs feed `nand`, `nand` feeds `not` (a NAND with both inputs tied together is a NOT), and `not` drives the output.
  </Step>

  <Step title="Simulate it">
    Simulation only advances when you ask it to.

    ```ts
    import { simulate } from "wires";
    import { AND } from "wires/components";

    const sim = simulate(AND);

    sim.set({ a: 1, b: 1 });
    sim.run();
    console.log(sim.read("out")); // 1

    sim.set({ a: 0 });
    sim.run();
    console.log(sim.read("out")); // 0
    ```
  </Step>

  <Step title="Look inside">
    Every simulator can report the value of every port in the hierarchy.

    ```ts
    import { simulate } from "wires";
    import { AND } from "wires/components";

    const sim = simulate(AND, { trace: true });
    sim.set({ a: 1, b: 1 });
    sim.run();

    console.log(sim.inspect().signals["root.nand.outputs.out"]); // 0
    console.log(sim.trace().length); // 4 transitions
    ```
  </Step>
</Steps>

<Tip>
  Port names are inferred from your definitions. `sim.read("nope")` or `add(NAND, "nand", { c: inputs.a })` fails at compile time, not at runtime.
</Tip>
