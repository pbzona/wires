## Install

<CodeGroup>

```bash pnpm
pnpm add @pbzona/wires
```

```bash npm
npm install @pbzona/wires
```

```bash bun
bun add @pbzona/wires
```

</CodeGroup>

`wires` is published on npm as `@pbzona/wires`. It needs Node.js 24, or 26 and later (no end-of-life releases), Bun, or any modern browser or bundler, and it has no runtime dependencies. The package has two entry points:

| Import | Contents |
| --- | --- |
| `@pbzona/wires` | The engine: `gate`, `circuit`, `bits`, `simulate`, `elaborate`, errors and types |
| `@pbzona/wires/components` | The standard library: `NAND`, `NOT`, `AND`, `OR`, `NOR`, `XOR`, `XNOR`, `HalfAdder`, `FullAdder`, `Mux`, `Demux`, `SRLatch`, `RegisterBit` |

## Build and simulate a circuit

<Steps>
  <Step title="Define a primitive gate">
    A primitive computes values. When the simulator evaluates NAND, `a` and `b` are signal values (`0`, `1` or `"X"`), and `out` is the value the gate produces.

    ```ts
    import { gate } from "@pbzona/wires";

    export const NAND = gate({
      name: "NAND",
      inputs: ["a", "b"],
      outputs: ["out"],
      evaluate: ({ a, b }) => ({
        out: a === 0 || b === 0 ? 1 : a === 1 && b === 1 ? 0 : "X",
      }),
    });
    ```

    The next example runs on its own. It imports this same NAND gate from `@pbzona/wires/components`.
  </Step>

  <Step title="Wire and test a ready light">
    A circuit connects wires. Name its pins for what they mean on that chip: a ready light needs to know whether the machine is `busy` and report whether the light is `lit`. The NAND inside it keeps its usual pins `a`, `b` and `out`.

    ```ts
    import { circuit, simulate } from "@pbzona/wires";
    import { NAND } from "@pbzona/wires/components";

    const ReadyLight = circuit(
      { name: "ReadyLight", inputs: ["busy"], outputs: ["lit"] },
      (chip) => {
        const busy = chip.inputs.busy;
        const inverter = chip.add(NAND, { a: busy, b: busy });
        chip.output("lit", inverter.outputs.out);
      },
    );

    const idle = simulate(ReadyLight).set({ busy: 0 }).run();
    console.log(idle.read("lit")); // 1

    const working = idle.set({ busy: 1 }).run();
    console.log(working.read("lit")); // 0
    ```

    `chip` is the builder for `ReadyLight`. Both NAND pins get the same wire, so the NAND inverts `busy`. Its `out` pin drives the light.

    `set()` queues the change; `run()` advances time until the circuit settles. Each returns a new state, so `idle` still shows the light on. To see the gate delay, [step through a simulation](/guides/running-simulations) or [trace a wire](/guides/introspection#trace).
  </Step>
</Steps>

<Tip>
  Port names belong to the chip that declares them. `working.read("lit")` is valid; `working.read("out")` is a type error because `out` belongs to NAND, not `ReadyLight`.
</Tip>
