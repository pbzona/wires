A composite circuit can become a part in another circuit. Start with a primitive NAND, build a NOT from it, then use that NOT alongside a second NAND to build an AND. Each [`circuit()`](/reference/circuit) call declares the new circuit's name and ports; its `(chip)` callback wires up the inside.

```ts
import { circuit, simulate } from "@pbzona/wires";
import { NAND } from "@pbzona/wires/components";

const NOT = circuit({ name: "NOT", inputs: ["a"], outputs: ["out"] }, (chip) => {
  const nand = chip.add(NAND, { a: chip.inputs.a, b: chip.inputs.a });
  chip.output("out", nand.outputs.out);
});

const AND = circuit({ name: "AND", inputs: ["a", "b"], outputs: ["out"] }, (chip) => {
  const nand = chip.add(NAND, { a: chip.inputs.a, b: chip.inputs.b });
  const inverter = chip.add(NOT, { a: nand.outputs.out });
  chip.output("out", inverter.outputs.out);
});

const sim = simulate(AND).set({ a: 1, b: 1 }).run();
console.log(sim.read("out")); // 1
```

Inside NOT, `chip.inputs.a` feeds both NAND inputs: tying them together turns NAND into an inverter. Inside AND, `chip` is a different builder. Its inputs feed `nand`, whose output feeds `inverter`. AND uses NOT's `a` and `out` ports without reaching inside it. Another circuit could now add AND the same way.

## The builder context

| Member | Description |
| --- | --- |
| `chip.inputs` | The circuit's own inputs. Use them as sources for the parts you add. |
| `chip.add(definition, wiring)` | Adds a primitive or composite, wires the inputs you list, and returns the part. |
| `chip.feed(part.inputs.x, source)` | Wires a part's input after the part has been added. |
| `chip.output(name, source)` | Drives one of the circuit's own outputs. |

Every wiring call reads **destination ← source**, like an assignment. In `chip.add(NOT, { a: nand.outputs.out })`, the destination is the inverter's `a` input and the source is the NAND's output. In `chip.output("out", inverter.outputs.out)`, the destination is AND's own `out` pin.

## Sources

A **source** is anything that can drive a wire:

- the circuit's own inputs (`chip.inputs.a`)
- the outputs of parts you've added (`nand.outputs.out`)

A part's inputs are never sources: they receive a signal, they don't produce one. One source can feed any number of inputs (fan-out), but each input has exactly one source.

## Wiring several bits

Declare related pins with [`bits(name, width)`](/reference/circuit#named-bit-groups) and keep unrelated pins named individually. For example, the [eight-bit register](/guides/eight-bit-register) has indexed data (`chip.inputs.d[i]`) alongside `chip.inputs.clock` and `chip.inputs.load`. To wire two registers in series, pass `d: first.outputs.q` in the second register's `chip.add` call instead of listing eight connections.

## Naming parts

`const inverter = chip.add(NOT, { a: nand.outputs.out })` gives you a local variable for wiring. It doesn't name the instance in the hierarchy. By default the builder assigns names like `NOT#0` and `NOT#1`, counting unnamed instances of each definition in order.

Pass a name as the second argument to `chip.add` when you want to recognize the part in an inspection path. For example, the [four-bit adder](/guides/four-bit-adder) names its stages `fa0` through `fa3`, so `root.fa3.or` identifies the OR inside the last stage. Explicit names must be identifiers and unique within the circuit; `inputs` and `outputs` are reserved.

## Feedback

Sometimes a part needs a signal from a part that comes later. Memory works this way. Leave that input out of the `chip.add` call, then wire it with `chip.feed` once the source exists:

```ts
import { circuit } from "@pbzona/wires";
import { NAND } from "@pbzona/wires/components";

const SRLatch = circuit(
  { name: "SRLatch", inputs: ["setN", "resetN"], outputs: ["q", "qBar"] },
  (chip) => {
    const qGate = chip.add(NAND, { a: chip.inputs.setN });
    const qBarGate = chip.add(NAND, { a: chip.inputs.resetN, b: qGate.outputs.out });
    chip.feed(qGate.inputs.b, qBarGate.outputs.out);
    chip.output("q", qGate.outputs.out);
    chip.output("qBar", qBarGate.outputs.out);
  },
);
```

The `chip.feed` call closes the loop: the gate driving `qBar` feeds the gate driving `q`. Cycles are never rejected just for being cycles. See [Sequential logic](/guides/sequential-logic) for how they behave.

The one exception is a loop made only of wires, with no gate anywhere in it. That can happen through pass-through composites, and since such a wire has no driver, it is reported when the circuit is elaborated.

## Checks

The builder checks your wiring and reports problems as a `CircuitError` prefixed with the circuit name. Most of them are also compile-time errors.

| Check | Example message |
| --- | --- |
| Input names the part doesn't have | `C: NAND has no input "c" (its inputs are a, b)` |
| Ports that don't exist | `C: n.inputs.b is not a port (got undefined); check that the port name exists` |
| A part's input used as a source | `C: b.inputs.a can't be used as a source for outputs.out: it's a component input, …` |
| Two sources for one input or output | `C: outputs.out has multiple drivers (inputs.a and inputs.b); …` |
| Output names the circuit doesn't have | `C: "other" is not an output of C (its outputs are out)` |
| Ports belonging to another circuit | `C: … belongs to circuit "Other", which is not part of this circuit …` |
| Duplicate, invalid or reserved part names | `C: Duplicate component instance name "x"` |

After the builder returns, every part input that was never wired and every output that was never driven is reported together:

```text
HalfBroken: Invalid circuit:
  - input n.inputs.b is not connected
  - output outputs.other is not driven
```

Unused circuit inputs and unused part outputs are fine.

## When the builder runs

The builder callback runs **immediately**, inside `circuit()`, and the result is checked before `circuit()` returns. A wiring mistake is reported where you define the circuit, not later when you first simulate it.

It also means a circuit can only contain parts that already exist. A circuit can never contain itself, so every circuit elaborates into a finite set of gates. Builders must be synchronous, and the builder context can't be used after the callback returns.
