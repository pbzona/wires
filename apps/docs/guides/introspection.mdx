Introspection is a first-class feature. There are four views, each serializable with `JSON.stringify`, and together they hold everything a frontend needs to draw a circuit and animate its signals.

| View | Call | Contains |
| --- | --- | --- |
| Topology | `definition.describe()` | The hierarchical structure: components, ports and connections |
| Netlist | `elaborate(definition)` | The flattened graph of primitives and the wires between them |
| State | `state.inspect()` | The current value of every port and wire, plus timing |
| Trace | `state.trace()` | Every wire change with its tick |

## Topology

`describe()` returns a `ComponentDescription` tree rooted at `"root"`:

```ts
import { AND } from "@pbzona/wires/components";

const d = AND.describe();
console.log(d.components.map((c) => `${c.id} (${c.definition}, ${c.kind})`));
// ["root.nand (NAND, primitive)", "root.not (NOT, composite)"]
console.log(d.connections[0]);
// { source: "root.inputs.a", destination: "root.nand.inputs.a" }
```

Each node has an `id` (its hierarchical path), its `name`, the `parent` id, the `definition` name, its `kind`, its `ports`, child `components` and internal `connections`. Primitives have empty `components` and `connections`. See [`ComponentDescription`](/reference/types#componentdescription).

Even when a builder wires a [named group](/reference/circuit#named-bit-groups), these views describe individual pins and connections. In the [eight-bit register](/guides/eight-bit-register), the input pin is `root.inputs.d3`, not `root.inputs.d[3]`; `inspect().signals["root.outputs.q3"]` gives the current value of one output. There is no `root.outputs.q` signal.

## Wires

A **wire** is one driver plus every port connected to it. The driver is either one of the circuit's inputs or a gate's output. Connections add no delay, so every port on a wire always has the same value.

A wire is named after its driver. In `AND`, the wire leaving the inner NAND is called `root.nand.outputs.out`, and it also reaches `root.not.inputs.a` and both inputs of the NOT's gate. That's why the trace and the netlist talk about wires, while `signals` lists every port separately.

## Netlist

[`elaborate()`](/reference/elaborate) returns the flattened graph that the simulator actually runs:

```ts
import { elaborate } from "@pbzona/wires";
import { AND } from "@pbzona/wires/components";

const netlist = elaborate(AND);
console.log(netlist.gates.map((g) => g.path)); // ["root.nand", "root.not.g"]
console.log(netlist.gates[1]?.ancestors);
// [{ id: "root", definition: "AND" }, { id: "root.not", definition: "NOT" }]
console.log(netlist.portWires["root.outputs.out"]); // "root.not.g.outputs.out"
```

Each wire lists its driver, every port on it, and the gates that read it. That's useful for highlighting a whole wire when one port is hovered.

## State

`inspect()` turns a simulation state into plain data:

```ts
import { simulate } from "@pbzona/wires";
import { AND } from "@pbzona/wires/components";

const settled = simulate(AND).set({ a: 1, b: 1 }).run();
console.log(settled.inspect());
```

```ts
{
  tick: 3,
  stable: true,
  pendingEvents: 0,
  signals: {
    "root.inputs.a": 1,
    "root.inputs.b": 1,
    "root.outputs.out": 1,
    "root.nand.inputs.a": 1,
    "root.nand.inputs.b": 1,
    "root.nand.outputs.out": 0,
    "root.not.inputs.a": 0,
    "root.not.outputs.out": 1,
    "root.not.g.inputs.a": 0,
    "root.not.g.inputs.b": 0,
    "root.not.g.outputs.out": 1
  },
  wires: {
    "root.inputs.a": { value: 1, ports: ["root.inputs.a", "root.nand.inputs.a"] },
    "root.inputs.b": { value: 1, ports: ["root.inputs.b", "root.nand.inputs.b"] },
    "root.nand.outputs.out": {
      value: 0,
      ports: ["root.nand.outputs.out", "root.not.inputs.a", "root.not.g.inputs.a", "root.not.g.inputs.b"]
    },
    "root.not.g.outputs.out": {
      value: 1,
      ports: ["root.outputs.out", "root.not.outputs.out", "root.not.g.outputs.out"]
    }
  }
}
```

- `signals` has an entry for **every port in the hierarchy**, in hierarchical order, so any port in a diagram can be colored directly.
- `wires` groups those ports by wire, so you can see that a value really is the same wire.

The state itself is immutable, and each snapshot is a fresh plain object.

## Trace

Enable tracing with `simulate(definition, { trace: true })`. It's off by default to save memory.

```ts
import { simulate } from "@pbzona/wires";
import { AND } from "@pbzona/wires/components";

const settled = simulate(AND, { trace: true }).set({ a: 1, b: 1 }).run();
console.log(settled.trace());
// [
//   { tick: 0, wire: "root.inputs.a", previous: "X", value: 1 },
//   { tick: 0, wire: "root.inputs.b", previous: "X", value: 1 },
//   { tick: 1, wire: "root.nand.outputs.out", previous: "X", value: 0 },
//   { tick: 2, wire: "root.not.g.outputs.out", previous: "X", value: 1 },
// ]
```

- Entries are ordered by tick, and by wire id within a tick, so traces are deterministic.
- `trace()` returns everything from tick 0 up to the state you call it on. Branches each have their own trace, and they share their common history.
- Each state also has `changes`: just the entries added by the step that produced it. That's handy when stepping with `step()`.

Traces are the raw material for timing diagrams and waveform views.
