Combinational circuits forget. Feed an output back into an input and a circuit can **remember**. `wires` allows arbitrary feedback, and its unit-delay simulation shows exactly how feedback circuits behave, including when they misbehave.

## The NAND SR latch

The standard [`SRLatch`](/library/memory) is two cross-coupled NAND gates with active-low controls:

```ts
import { circuit } from "wires";
import { NAND } from "wires/components";

const SRLatch = circuit(
  { name: "SRLatch", inputs: ["setN", "resetN"], outputs: ["q", "qBar"] },
  ({ inputs, add, feed, output }) => {
    const top = add(NAND, "top", { a: inputs.setN }); // b is fed back below
    const bottom = add(NAND, "bottom", { a: inputs.resetN, b: top.outputs.out });
    feed(top.inputs.b, bottom.outputs.out); // the feedback wire
    output("q", top.outputs.out);
    output("qBar", bottom.outputs.out);
  },
);
```

`top` needs `bottom`'s output, but `bottom` doesn't exist yet when `top` is added. So `top`'s input `b` is left out of the `add` call and wired afterwards with [`feed`](/guides/composing-circuits#feedback). Each part feeds the other, and that loop is what lets the latch remember.

## Storing a bit

```ts
import { simulate } from "wires";
import { SRLatch } from "wires/components";

const latch = simulate(SRLatch);

latch.set({ setN: 1, resetN: 1 });
latch.run();
console.log(latch.readAll()); // { q: "X", qBar: "X" }: never initialized

latch.set({ setN: 0 }); // set
latch.run();
latch.set({ setN: 1 }); // release
latch.run();
console.log(latch.readAll()); // { q: 1, qBar: 0 }: remembers 1

latch.set({ resetN: 0 }); // reset
latch.run();
latch.set({ resetN: 1 }); // release
latch.run();
console.log(latch.readAll()); // { q: 0, qBar: 1 }: remembers 0
```

| setN | resetN | Result |
| --- | --- | --- |
| 0 | 1 | Set: `q = 1`, `qBar = 0` |
| 1 | 0 | Reset: `q = 0`, `qBar = 1` |
| 1 | 1 | Hold the previous state (`X` if never initialized) |
| 0 | 0 | Forbidden: `q = qBar = 1` |

## Unknown state is a real state

A latch that has never been set or reset settles into a **stable unknown** state. `run()` returns normally and both outputs read `"X"`. The simulator does not pick a value for you, because a real latch powers up in an unpredictable state.

## The forbidden state

Holding both controls low drives both outputs to `1`. That isn't a complementary state, so it can't be stored. Releasing both controls in the same tick starts a race: both gates flip to `0` together, then back to `1` together, forever. `run()` detects this and throws a `StabilizationError` instead of quietly choosing a winner.

```ts
import { simulate, StabilizationError } from "wires";
import { SRLatch } from "wires/components";

const latch = simulate(SRLatch, { maxTicks: 50 });
latch.set({ setN: 0, resetN: 0 });
latch.run();
console.log(latch.readAll()); // { q: 1, qBar: 1 }

latch.set({ setN: 1, resetN: 1 });
try {
  latch.run();
} catch (error) {
  console.log(error instanceof StabilizationError); // true
}
```

## Oscillators

An odd number of inverters in a loop has no stable state. This ring oscillator gates its loop with a NAND, so it can be held still while `enable = 0`:

```ts
import { circuit, simulate, StabilizationError } from "wires";
import { NAND, NOT } from "wires/components";

const Ring = circuit({ name: "Ring", inputs: ["enable"], outputs: ["out"] }, ({ inputs, add, feed, output }) => {
  const gate = add(NAND, "gate", { a: inputs.enable }); // b is fed back from inv2
  const inv1 = add(NOT, "inv1", { a: gate.outputs.out });
  const inv2 = add(NOT, "inv2", { a: inv1.outputs.out });
  feed(gate.inputs.b, inv2.outputs.out);
  output("out", inv2.outputs.out);
});

const sim = simulate(Ring, { maxTicks: 100, trace: true });
sim.set({ enable: 0 });
sim.run(); // stable, out = 1

sim.set({ enable: 1 });
try {
  sim.run();
} catch (error) {
  if (!(error instanceof StabilizationError)) throw error;
  console.log(error.components); // ["root.gate", "root.inv1.g", "root.inv2.g"]
}

sim.set({ enable: 0 }); // stop it, and the simulator settles again
sim.run();
```

With three one-tick stages, the output toggles every three ticks. Step through it with `tick()` and read the timing from `trace()`.

If you never set `enable`, the loop stays at `"X"`. That's a stable unknown, not an oscillation, because nothing ever changes.
