Combinational circuits forget. Feed an output back into an input and a circuit can **remember**. `wires` allows arbitrary feedback, and its unit-delay simulation shows exactly how feedback circuits behave, including when they misbehave.

## The NAND SR latch

The standard [`SRLatch`](/library/memory) is two cross-coupled NAND gates with active-low controls:

```ts
import { circuit } from "@pbzona/wires";
import { NAND } from "@pbzona/wires/components";

const SRLatch = circuit(
  { name: "SRLatch", inputs: ["setN", "resetN"], outputs: ["q", "qBar"] },
  (chip) => {
    const qGate = chip.add(NAND, { a: chip.inputs.setN });
    const qBarGate = chip.add(NAND, { a: chip.inputs.resetN, b: qGate.outputs.out });
    chip.feed(qGate.inputs.b, qBarGate.outputs.out);
    chip.output("q", qGate.outputs.out);
    chip.output("qBar", qBarGate.outputs.out);
  },
);
```

The NAND that drives `q` needs a signal from the NAND that drives `qBar`. When `chip.add` creates `qGate`, that second gate doesn't exist yet, so leave `b` unwired. Once both gates exist, [`chip.feed`](/guides/composing-circuits#feedback) connects `qBarGate.outputs.out` back to `qGate.inputs.b`. Each gate now feeds the other, and that loop is what lets the latch remember.

## Storing a bit

```ts
import { simulate } from "@pbzona/wires";
import { SRLatch } from "@pbzona/wires/components";

let latch = simulate(SRLatch);

latch = latch.set({ setN: 1, resetN: 1 }).run();
console.log(latch.readAll()); // { q: "X", qBar: "X" }: never initialized

latch = latch.set({ setN: 0 }).run(); // set
latch = latch.set({ setN: 1 }).run(); // release
console.log(latch.readAll()); // { q: 1, qBar: 0 }: remembers 1
const rememberedOne = latch;

latch = latch.set({ resetN: 0 }).run(); // reset
latch = latch.set({ resetN: 1 }).run(); // release
console.log(latch.readAll()); // { q: 0, qBar: 1 }: remembers 0
console.log(rememberedOne.readAll()); // { q: 1, qBar: 0 }: earlier states never change
```

| setN | resetN | Result |
| --- | --- | --- |
| 0 | 1 | Set: `q = 1`, `qBar = 0` |
| 1 | 0 | Reset: `q = 0`, `qBar = 1` |
| 1 | 1 | Hold the previous state (`X` if never initialized) |
| 0 | 0 | Forbidden: `q = qBar = 1` |

## Unknown state is a real state

A latch that has never been set or reset settles into a **stable unknown** state. `run()` returns normally and both outputs read `"X"`. The simulator does not pick a value for you, because a real latch powers up in an unpredictable state.

## The forbidden state

Holding both controls low drives both outputs to `1`. That isn't a complementary state, so it can't be stored. Releasing both controls in the same tick starts a race: both gates flip to `0` together, then back to `1` together, forever. `run()` detects this and throws a `StabilizationError` instead of quietly choosing a winner.

```ts
import { simulate, StabilizationError } from "@pbzona/wires";
import { SRLatch } from "@pbzona/wires/components";

const forbidden = simulate(SRLatch, { maxTicks: 50 }).set({ setN: 0, resetN: 0 }).run();
console.log(forbidden.readAll()); // { q: 1, qBar: 1 }

try {
  forbidden.set({ setN: 1, resetN: 1 }).run();
} catch (error) {
  console.log(error instanceof StabilizationError); // true
}
```

## Oscillators

An odd number of inverters in a loop has no stable state. This ring oscillator gates its loop with a NAND, so it can be held still while `enable = 0`:

```ts
import { circuit, simulate, StabilizationError } from "@pbzona/wires";
import { NAND, NOT } from "@pbzona/wires/components";

const Ring = circuit({ name: "Ring", inputs: ["enable"], outputs: ["out"] }, (chip) => {
  const gate = chip.add(NAND, "gate", { a: chip.inputs.enable });
  const inv1 = chip.add(NOT, "inv1", { a: gate.outputs.out });
  const inv2 = chip.add(NOT, "inv2", { a: inv1.outputs.out });
  chip.feed(gate.inputs.b, inv2.outputs.out);
  chip.output("out", inv2.outputs.out);
});

const still = simulate(Ring, { maxTicks: 100, trace: true }).set({ enable: 0 }).run(); // stable, out = 1
const running = still.set({ enable: 1 });

try {
  running.run();
} catch (error) {
  if (!(error instanceof StabilizationError)) throw error;
  console.log(error.components); // ["root.gate", "root.inv1.g", "root.inv2.g"]
}

console.log(running.set({ enable: 0 }).run().read("out")); // 1: stopped, and settled again

// Step through the oscillation and watch the output
let stepped = running;
for (let i = 0; i < 12; i++) stepped = stepped.step();
const outputChanges = stepped.trace().filter((change) => change.wire === "root.inv2.g.outputs.out");
console.log(outputChanges.map((change) => `@${change.tick}: ${change.value}`));
```

With three one-tick stages, the output toggles every three ticks. The instance name `inv2` lets you find the last inverter in the trace: `root.inv2.g.outputs.out` is the output of the NAND named `g` inside that standard NOT.

If you never set `enable`, the loop stays at `"X"`. That's a stable unknown, not an oscillation, because nothing ever changes.
